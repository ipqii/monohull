## Project Overview

Monohull is a Spring Boot application with a React web UI that orchestrates Docker containers for IBM Maximo® development environments. It manages three containers per environment: a database (DB2 or Oracle), a WebSphere application server, and an administration tool container.

- **Java 17**, **Spring Boot 3.3.4**, **Maven**
- **Spring MVC** (spring-boot-starter-web) with **reactor-core** for SSE log streaming
- **JPA + MariaDB + Flyway** for persistence
- **React + TypeScript + Vite + MUI** frontend
- Docker managed via `docker-java` library

## Build & Run Commands

The build needs JDK 17. If your system default `java` is older, point JAVA_HOME at a JDK 17 first (PowerShell example):

```powershell
$env:JAVA_HOME="C:\path\to\jdk-17"; $env:Path="$env:JAVA_HOME\bin;$env:Path"
```

```bash
# Build (compiles Java + builds React frontend)
mvn clean package

# Run tests
mvn test

# Run a single test class
mvn test -Dtest=ClassName

# Run the application (requires MariaDB)
mvn spring-boot:run

# Or run the packaged JAR (finalName is version-independent)
java -jar target/monohull.jar

# Frontend dev server (proxies /api to localhost:8080)
cd frontend && npm run dev
```

### Frontend Design System

The UI uses MUI v5 with a heavily customized dark theme defined in `frontend/src/main.tsx`. When adding new components or pages, follow these conventions so the visual language stays consistent:

- **Palette:** dark slate backgrounds (`#0a0e1a`, `#111827`), indigo primary (`#6366f1`), cyan secondary (`#22d3ee`), with `success`/`warning`/`error` status colors. The background has a subtle radial gradient applied via `MuiCssBaseline`.
- **Typography:** Inter for UI text, JetBrains Mono for any code/terminal/monospace display (commands, image tags, log output, build IDs).
- **Cards & Papers:** automatically get glassmorphism (`backdrop-filter: blur(12px)`, translucent bg, thin indigo border) through theme overrides — do NOT add `bgcolor` or `background` to `<Card>`/`<Paper>` directly unless you want to override the glass effect.
- **Layout:** `App.tsx` renders a permanent sidebar (260px wide, temporary drawer on mobile). Main content lives under a `<Box component="main">` with its own padding — pages should NOT wrap themselves in a `<Container>`.
- **Status display:** use `<ContainerStatusBadge>` (dot + uppercase label with pulse animation for active states) rather than raw MUI `<Chip>` for statuses.
- **Empty states:** use a centered `<Box>` with dashed indigo border (`border: '1px dashed rgba(99, 102, 241, 0.2)'`) rather than `<Alert severity="info">`.
- **Loading states:** use MUI `<Skeleton>` matching the shape of the eventual content, not `<Typography>Loading...</Typography>`.
- **Page headers:** title (`<Typography variant="h4">`) + secondary description line + primary action button on the right, with `mb: 4` spacing.
- **Section dividers:** uppercase `<Typography variant="subtitle2">` with a thin horizontal rule, not `<Typography variant="h6">`.
- **Log display:** always use the `<LogViewer>` component — it has terminal chrome (window dots, filename, copy/download buttons) and handles line numbering + error/warn line coloring.

### Request Flow

**Legacy:** `BuildController` → `BuildService` (@Async) → `DockerService` → Docker daemon
**New UI:** `EnvironmentController` → `EnvironmentService` → `BuildService.startBuildForEnvironment()` → `DockerService`
**Logs:** `LogController` / `EnvironmentController` ← `LogSink` (Flux<String> via SSE)
**Actions:** `ActionController` → `ActionService` → `DockerService` (exec in container or host-level Docker ops)
**Pipelines:** `ActionController` → `ActionService.startPipeline()` → sequential action execution per environment

### Key Components

- **`EnvironmentService`** — Main orchestration: create/list/stop/start/remove environments, per-container ops, live Docker status enrichment.
- **`BuildService`** — Async build orchestration. `startBuild(BuildRequest)` for legacy API, `startBuildForEnvironment(id)` for UI-driven builds with DB persistence.
- **`DockerService`** — Wraps `docker-java` client: container CRUD, inspect, start/stop/restart, exec, managed container listing.
- **`ActionService`** — Action management and execution: built-in actions (from `application.yml`), custom actions (DB-backed), pipeline orchestration, action log streaming.
- **`PipelineDefinitionService`** — CRUD for pipeline definitions (ordered sequences of actions).
- **`LogSink`** — Reactive log accumulator using `Sinks.Many<String>`.
- **`ActionProperties`** — `@ConfigurationProperties` reading built-in action definitions from `application.yml`.
